# Rusty Download Manager v0.1.0 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task.

**Goal:** Deliver the approved branded Windows release with tray/background operation and local installation artifacts.

**Architecture:** Keep the engine and capture endpoint in the existing single GUI process. Add a native tray owner and background launch mode; distribute the GUI, native host and extension through a current-user Inno Setup installer and portable archive.

**Tech Stack:** Rust, Win32, PowerShell, Python packaging and Inno Setup.

**Spec:** ../specs/2026-10-19-v0.1.0-release-design.md

## Global Constraints

- Windows 10/11 x64, product Rusty Download Manager, version 0.1.0.
- Use the existing feature worktree and current-user installation paths.
- Do not alter Chrome profiles or bypass extension/website permission approval.
- Preserve settings, downloads and valid existing native-host ownership on upgrade.
- No test suites or dev server; necessary release/setup compilation is authorized.
- Do not run the resulting installer or interrupt active downloads.
- Delegated reviews use GPT-6.1 Sol only.

## Review Focus

- Second hidden launch must not reveal the manager or start another engine.
- Explorer restart must recreate the tray; failed tray creation must leave visible UI.
- Shutdown/logoff must not be vetoed or trigger a blocking cancellation prompt.
- Upgrade/removal must refuse to replace active binaries and preserve unrelated files.
- A fresh Chrome installation must register the real extension ID, not a machine-specific guess.
