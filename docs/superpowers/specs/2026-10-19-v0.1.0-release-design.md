# Rusty Download Manager v0.1.0 release

## Requested outcome

Finalize the existing native Windows download manager as Rusty Download Manager
v0.1.0: original application icon, complete installation package, and background
download capture after installation. Include the context menu and compact
completion/progress changes already committed on `codex/chrome-download-capture`.

This document describes the proposed release. Implementation and release
artifacts have not been produced for this scope yet.

## Product and platform

- Keep actual Win32/common controls, compact Tahoma dialogs and independent Rusty
  branding. Display **Rusty Download Manager** and **0.1.0** consistently in the
  title, About, executable version resources, tray, shortcuts and installer.
- Windows 10/11 x64, current-user installation without an administrator prompt.
- Original, readable download-arrow/R mark in rust orange and graphite; these
  colors belong to branding assets and do not change the native control theme.
  Produce editable vector artwork, PNG sizes and a multi-resolution application
  ICO. Embed it in the executable and use it for windows, tray, shortcuts and setup.
- Produce a versioned installer EXE, portable ZIP, browser-extension ZIP, release
  notes, user setup guide and SHA-256 checksums. Artifacts are local; publishing
  a GitHub release or Chrome Web Store listing is outside this request.

## Continuous background use

- Setup offers **Start Rusty when I sign in**, selected by default, and launches
  Rusty in background mode after installation. The installed program registers a
  per-user login startup entry pointing at the quoted installed executable with
  `--background`.
- Background mode creates the engine, secured browser endpoint and notification
  area icon while keeping the main window hidden. Downloads and capture continue
  when the main window is closed or minimized. Close hides the main window;
  the explicit tray/menu **Exit** command confirms cancellation of active work
  and follows the existing asynchronous cleanup/join path.
- Tray offers Open Rusty Download Manager, Add URL, Options and Exit. Double-click
  opens the manager. The icon is restored if Explorer restarts, and is removed on
  exit. If the tray cannot be established, show the manager so it remains usable.
- Starting Rusty normally reveals the existing instance. Starting it with
  `--background` does not reveal an existing instance or create a second engine.
  Browser-launched instances also start in background mode; capture dialogs still
  come forward when user interaction is required.
- Background operation means while Windows is awake and the user is signed in.
  It does not prevent sleep, survive a powered-off PC, run as a system service,
  or restart after an explicit Exit. Persisting downloads across logout/reboot
  remains outside v0.1.0; current history is session-only.
- Windows logoff/shutdown must not be vetoed by the existing WM_QUERYENDSESSION
  handler. Begin cancellation without a user prompt when the session actually
  ends; retain the existing guarded partial-file/recovery behavior.

## Chrome capture and first installation

- Keep the existing user/session security, native-host framing, exact allowed
  extension origin, lease/acknowledgement handoff and browser fallback behavior.
- Chrome requires user approval of an extension and its optional website access.
  Setup cannot silently install an unpublished extension on ordinary Windows.
  Do not modify Chrome profiles, bypass its approval, or set enterprise policies.
- Bundle the unpacked extension in a stable installed `chrome-extension` path.
  Include a clearly named Chrome Integration setup helper and Start menu shortcut
  that walks through Load unpacked, accepting site access/automatic capture, and
  the exact extension ID registration. On this PC preserve the existing extension
  registration (`ipolekmihgpdbmelheajogmgnjgmenol`) and the stable existing paths.
- Discover and reuse a valid Rusty-owned registration during upgrade. Fresh
  installation accepts an exact Chrome extension ID through the helper; never
  assume another machine has this PC's unpacked ID. Preserve user capture choices
  during upgrades. First-time setup explicitly guides the user to enable capture.
- Once the extension is loaded, capture is enabled and the helper registers its
  exact ID, capture works after every login without opening the main window.
  The native host can start Rusty if it is not already running.
- Scope remains supported public HTTP/HTTPS GET downloads. Browser-authenticated,
  streaming/blob/DRM downloads and unavailable native-host handoffs retain the
  existing browser fallback. The existing file-info prompt remains part of capture.

## Setup, upgrade and removal

- Use Inno Setup to install into `%LOCALAPPDATA%\RustyIDM` with the existing
  `bin` and `chrome-extension` subpaths, preserving settings and registration data.
  Include application/native-host executables, branding, extension, setup helper,
  register/unregister scripts, license and user documentation.
- Add Start menu and optional desktop shortcuts plus a standard uninstaller.
  Login startup is an explicit visible installation task, default enabled.
- Do not replace running application binaries or interrupt active downloads.
  Setup asks users to exit Rusty before upgrades/removal; helper failures are
  visible and do not claim integration succeeded.
- Remove only installation-owned files, shortcuts, startup entry and matching
  native-host registration on uninstall. Preserve downloaded files and saved
  preferences; do not delete the whole LocalAppData tree recursively.
- Portable ZIP runs without installation and does not register startup or a
  native host automatically. Settings remain in the existing LocalAppData store;
  label this explicitly rather than claiming isolated portable data storage.
- Unsigned local release: do not claim a signing certificate or reputation that
  does not exist. Windows may show its normal publisher/reputation prompts.

## Execution and evidence

- Reuse the existing feature worktree. No changes to the older D: main checkout
  or unrelated work. All new agent delegation, if needed, must use GPT-6.1 Sol.
- This release request authorizes the necessary optimized Windows build and setup
  compilation, along with obtaining the official packaging compiler if absent.
  Avoid repeated builds and do not run a development server.
- Do not add/run test suites without a user request. Run existing source checks,
  inspect the Rust/native resource changes, inspect packaged contents, verify
  version information and checksums, and report any behavior not exercised live.
- Produce the installer and portable files; do not silently run the new setup,
  change Chrome permissions, publish artifacts, or stop a running download.

## Acceptance checklist

- App, executable and setup show the correct product/version and original icon.
- Closing the manager leaves the engine and tray available; explicit Exit cleans up.
- Login startup is hidden and idempotent; Explorer restart restores the tray icon.
- Capture setup clearly distinguishes app installation from Chrome approval and
  preserves existing exact-origin registration on upgrade.
- Installed and portable deliverables contain all runtime files, documentation
  and branding, with matching recorded SHA-256 checksums.
- Existing context menu, compact completion window and automatic successful
  progress-window closure are retained in the release build.
